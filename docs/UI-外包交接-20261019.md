## 2. 当前 Demo 是什么

主玩法是 5×5 格子高塔：

- 1–100F，每 10F 一个区段，100F Boss。
- 迷雾、月光步数、警戒、钥匙、宝箱、机关、安全屋、守卫、影子房。
- 1–20F 外环、21–40F 腐蚀区、41–60F 聚光区、61–80F 钟摆区、81–100F 镜厅区。
- 影子房可以自由输入交涉；成功清房，失败进入战斗。
- 战斗舞台按敌人数逐只渲染立绘位，点谁选谁。
- 据点下方有一个「AI LAB / 试验层」，是 3–5 间房的短流程，只用于验证 AI。

外包 UI 时，以上规则和页面结构应视为已冻结；如确需改结构，先出对照表。

## 4. 每个页面都要处理的状态

- 默认：有存档、有 Persona、有道具。
- 空：没有存档 / 没有 Persona / 没有道具 / 没有昨夜记录。
- 锁定：塔门未开、未觉醒、另外两座塔未开放。
- 加载：AI 显形、AI 判定、行动演出（按钮禁用、有明确“它在听/正在显形”）。
- 失败/兜底：模型不可用时明确显示“离线判定”，不伪装成真实 AI。
- 忙碌：行动演出中禁止重复点击。
- 窄屏：390×844 与 320×568；不横向溢出、不挡按钮。

### 6.1 主题交付方式（P3 / P4 / P5）

- **先交 P3 完整版**：当前 DOM、变量、素材位和验收都以 P3 为基准。
- **P4 / P5 不另起三套 demo**：在同一套 DOM、同一套 `data-*` 钩子上，交 `theme-p4.css` / `theme-p5.css` + 对应素材；页面结构和交互完全共用。
- 三个主题共用一份存档、一套规则、一套页面；只换配色、字体、转场、Cut-in、音效和素材。
- 如果一定要交三个独立 demo：三套必须同 DOM、同钩子，并附 `THEME-MAP.md`；否则接回时会被当成三套代码，不接。
- P4/P5 的新生成素材先给用户看成品，验收后再接入。

### 6.2 三主题可以不同排版

允许，而且鼓励做出明显区别：

- 同一套 DOM 下，用 CSS 重排：`grid-template-areas`、`order`、绝对定位、不同 HUD 位置、不同指令区方向、不同转场。
- 每个主题可以有独立的背景、装饰层、边框、字体、动效和 Cut-in；P3 可以纵向指令列，P4 可以做电视框/遥控器式底栏，P5 可以做斜切海报式布局。
- 但页面清单、`data-*` 钩子、状态（空/锁定/加载/失败/忙碌）和关键反馈（点怪选目标、`ALLY TURN`）必须在三个主题里一致存在。

不允许：

- 三套独立 DOM、三套 `app.js`、三套各自演化的交互。
- 用 `transform: skew()` / `clip-path` 把按钮的点击区一起缩小；视觉可以斜，点击区要正。
- 只在桌面做排版，手机端直接缩桌面版；每个主题都要单独过 390 和 320。

交付时附 `THEME-MAP.md`，写清每个主题的关键区块位置（HUD、地图、指令区、敌人位、结算卡）和移动端重排方式。

## 7. 交互契约（硬性）

以下属性是 JS 事件入口，**不能改名、不能删除、不能只在视觉上仿造**：

- `data-action`：全局动作（设置、开塔、执行、返回等）
- `data-tower`：塔内动作（`prep-*`、`move:*`、`room:x:y`、`shadow-talk*`、`rest`、`retreat` 等）
- `data-slice`：AI LAB 动作（`plan-tower`、`plan`、`sneak`、`fight`、`talk`、`talk-send`、`continue`、`settle`、`back-day`）
- `data-target-id`：点敌人立绘/卡片切目标
- `data-battle-action`：战斗指令
- `data-holdup-engine`：Hold Up 的总攻击/交涉/放它们起来
- `data-map-viewport`、`data-room`：地图拖动/寻路
- `data-art-slot`：素材位

如果新 DOM 必须改结构，交付时附一份 `HOOK-MAP.md`：

```text
旧钩子 → 新元素 / 新钩子
data-target-id="a" → .enemy-card[data-target-id="a"]
...
```

没有这份映射，接回时会被当成“重新接线”，不是微调。
