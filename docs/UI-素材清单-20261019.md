## 从原画导出的版本，不增加生成数量

- Persona：导出 440×640 塔罗内容图、600×600 名录图、256×256 头像。保留透明留白，让现有四主题卡框适配；不要把卡框、角色名、HP 或等级画进图里。
- 普通敌人：导出 600×600 显示图与 256×256 头像。两只敌人的形状要能直接区分；不要只换颜色。
- Cut-in：现有 P3-E 有主角和三队员四个显示位，规格 480×760。先从已选原画裁切；裁切效果不足时再追加专用动作图，不能把四个显示位误算成固定四个角色。
- 总攻击 P3-F：现有 2400×1120 剪影穿梭可用同批透明角色合成；斩线、速度线、字样保留代码绘制，不急于生成整张动画截图。

## 每张图的交付要求

1. 原画、透明版本与裁切衍生图分开交付，文件名使用上述稳定 ID。不要用白底假装透明。
2. 主体四周留约 8%–12% 安全区，不切断手、武器、角、翅膀或脚；脸和识别特征不能顶住卡框。
3. 不画按钮、卡框、主题底纹、文字、血条、楼层与数字；动态信息继续由程序显示。
4. 四主题复用同一原画，主题色仅作轻量外部效果；红色战斗页的现有排版与配色不因此改变。
5. 先检查实际图片、透明通道及同屏两敌可辨性，再展示给用户审核。审核通过后才接入；本轮没有生成或应用任何新图。

## 接入边界

当前 `art.js` 只有 `hero` / `enemy` 两个总入口，且 `approvedArt` 仍是空值；多敌人头像还在 `app.js` 里使用同一内联 SVG。Persona 名录和 Boss 两阶段也需要按角色 ID 接线。因此清单是已核位置后的制作建议，不能承诺把 14 个文件放进目录就会自动出现。

后续顺序：先选一张 Persona 和一只敌人做样张 → 用户审核画风 → 再生成同批其余素材 → 用户逐批审核 → 由 Codex 按角色 ID 接入既有槽位并跑四主题回归。生图调用按当时的 `gpt-image` 技能执行，尚未授权的付费调用不在本轮执行。
