# app

## 对 TASK-APP-v1.1 的意见

- **v1.1 已经把 App 侧最重要的几个口子收住了。** 删除 `handlers`、要求数据深冻结、先提交再演出、双轨道、缓冲满保留最新、组合预算、粒子总上限、滤镜白名单、`env` 快照和交涉模板白名单，都对应了 v1 评审里的风险；这些按现在的文字可以进入实现。
- **`DeepReadonly` 是编译期约束，运行时必须再补一层强制。** 引擎发给皮肤前要做 `Object.freeze` 或 `structuredClone`；验收项已经写了“写属性抛错或无效”，但实现上还要覆盖数组、嵌套对象、`Map/Set` 和 Pixi 资源引用，不能只冻结顶层。
- **交涉是最容易把“先提交再演出”破坏掉的一处。** `talk:start` 后进入玩家可停留的 DOM 界面，而 AI 请求又不该阻塞主循环。需要明确：交涉 UI 是独立于 Director 的交互阶段，只在 `talk:result` 前由规则做一次可验证的提交；AI 只生成对白，不参与胜负判定，超时用规则兜底台词，不能把网络耗时算进任何演出上限，也不能让玩家重复触发结算。
- **`env:change` 排到主线空隙需要一个有界的等待策略。** 建议只保留 1 个待播快照，后到覆盖先到；空隙太短时可以跳过低优先级 env 演出，但不丢失最新 `env` 值。否则连续日期变化或多次影时间切换会堆积到主线尾部。
- **`rewarm()` 的“新触发中断进行中的 rewarm”要避免高频自打断。** 300ms 合并已经解决大部分问题，但中断后再重来可能永远完不成。建议中断前只取消当前步骤，保留已完成的离屏滤镜缓存；同一尺寸已预热直接返回，进入游戏前没有可用结果就冷启动，不阻塞入口。
- **皮肤包里“唯一 TS 是 `index.ts`，只做组装和注册”需要给一个极窄的合法边界。** 禁止演出逻辑不等于禁止读 manifest、建映射和生成 `registerSkin` 参数；`skin:check` 应允许声明式的 const、数组展开和标签映射，但拒绝定时器、DOM 查询、store、网络和任何运行时分支逻辑。
- **`repeatEvery` 展开要有总轨道数上限。** 否则一个小数或大 `times` 会在加载期生成几千条轨道，既拖慢 `skin:check`，也可能绕过时长预算。建议限制每个 recipe 展开后的轨道数，并把该限制写进 manifest/schema 错误信息。
- **`hitMarks` 需要更硬的校验，不能只查上限。** 应要求升序、无负数、数量等于 `payload.hits.length`，且 `hitMarks + 命中后视觉余量` 不能越过 `duration`。多目标命中时还要写清 `hitMarks` 是否按目标聚合，避免皮肤和引擎对“命中时刻”理解不一致。
- **粒子总上限和滤镜白名单已经有量化，但回收必须验证到“演出结束后瞬时为 0”。** 尤其重叠层 `unit:down` 和主线 banner/cutin 同时存在时，对象池要按 owner 释放，不能只隐藏不回收；否则切皮肤和连续战斗会慢慢泄漏。
- **`source: official | generated` 不能只是标注，还要阻断误发。** 官方素材存在版权风险；`skin:check` 和打包脚本应能区分官方素材只进私有仓库，生成素材才能走公开/CDN。App 侧至少要有机器可读标记，不能靠人工自觉。
- **字体和素材预算需要与首包上限统一检查。** manifest 已写字体 120KB，但 `p5r-compendium-data` 这类 2.2MB 数据不在皮肤包内，仍是 App 集成侧的主包风险。v1.1 没有解决它，M3 前要单独确认图鉴是否按需分片。
- **`ui:open/ui:close` 不进 Director 是合理简化，但要明确它们不能抢占主线输入。** HUD/DOM 过渡应当非阻塞且可被打断，不产生 `signal.abort()` 责任；否则“不进 Director”会被实现成另一个不受控的动画系统。
- **虚拟横屏的触摸坐标变换要覆盖 DOM 模板，不只 Pixi。** 交涉模板、设置和 HUD 是 DOM，±90° 旋转时只改 canvas 坐标不够；`skin:check` 或验收应明确 DOM 模板也在逻辑安全矩形内做输入命中，避免低档 0.85 时命中漂移。
- **`skin:check` 的 import 校验应做完整 AST，而不是字符串匹配。** 静态 import 好查，但要同时挡住注释、模板字符串拼接、`import()`、`require`、`import.meta.glob` 和 `import 'x'`；`rules/`、`ui/`、App store 都列入黑名单，错误信息要给出具体文件、行和命中的导入路径。
- **强杀进程后只提交一次的前提是 checkpoint 先落 Dexie。** `checkpointId` 需要在内存状态更新前持久化，重启时先按 checkpoint 幂等恢复，不能先 `set()` 再异步写库；这个顺序如果反了，验收里的“强杀进程再进只提交 1 次”会失败。
- **`env` 的 `moonPhase`、`darkHour` 要定义清楚时区和数据源。** `date/weekday` 用本地日期，`moonPhase` 用固定公式，`darkHour` 从 App 设置取；天气未知填 `'unknown'`。这些必须由 App 层单点计算，不能让皮肤按系统时间重算，否则同局内会出现不一致。
