# UMBRA 重制策划案 v1 · 评审 · p3-blue（蓝 / P3R）

## 1. 哪里做不到，为什么
- **交涉没有 P3 原作版式**：P3/P3R 没有面具交涉（对应的是 Shuffle Time）。蓝皮交涉只能用 P3R 菜单语言自创，需要契约允许皮肤自定交涉演出。
- **召唤演出的敏感性**：P3 招牌是召唤器对头扣扳机 → 玻璃碎裂 → 面具出现。商店上架和低龄用户可能有问题，需要用户先定：照做、弱化（只做玻璃碎裂和蓝色冲击），还是改成别的。
- **影时间绿色滤镜占预算**：P3 的影时间要整屏绿调 + 血月，按"同屏滤镜 ≤2"规则会和命中特效抢预算。需要契约允许用预烘焙的配色/背景图代替实时滤镜。
- **"攀登塔层"与节点地图**：塔耳塔罗斯原作是随机走廊，没有插画俯视图可参照，地图插画需新做。

## 2. 哪里想改，建议怎么改
- 蓝皮 HIGHLIGHT 直接对应 P3R 的 Theurgy（专属大招），演出规格写进 cutins，简短版 1.2s 同样适用。
- 原语清单加入：玻璃碎裂、斜切色带扫屏、日期翻页（P3R 招牌转场）。
- 战斗指令在 P3R 是右侧斜列文字菜单，与第八节的"拇指弧形按钮"冲突。建议插槽允许皮肤改成斜列样式，只要命中区仍 ≥72 逻辑像素、在拇指区内。

## 共同问题（三主题一致，单独列出便于汇总）
- **事件 Promise 会卡输入**：皮肤返回的 Promise 由引擎等待，皮肤写错一个就整场卡死。建议契约规定每个事件的时长上限（如 onemore ≤0.45s、allout ≤3.5s），按倍速缩放，超时引擎强制推进；演出期间输入进预缓冲队列，满足"动画播放中也能点下一项"。
- **recipes 格式要早冻结**：皮肤包工作全部依赖 recipes JSON 和特效原语清单。建议 M1 结束就出原语清单 + recipe schema 草案（M3 再定稿），主题方在 M2/M3 并行做素材拆层和定格画，不必等到 M4。
- **宿主桥写法矛盾**：规则并入 `src/umbra`，但宿主桥仍是 postMessage，是否意味着继续 iframe？请明确：同包懒加载模块（推荐，可直接读 store、省掉存档同步）还是 iframe 隔离。
- **布局插槽**：第八节战斗布局是固定的。皮肤能否改插槽外观、位置微调和形状（P3 的斜切列表、P4 的方块菜单），只要不越出安全区和拇指弧？建议契约给"插槽 + 可覆盖样式 token"，而不是完全锁死或完全放开。
- **命名可覆盖**：委托板、心之卡、HOLD UP、异界名、怪盗等级等文案，契约里允许皮肤按原作改名（规则 id 不变）。
- **预算写进契约**：每个皮肤首包大小、图集张数、纹理内存、ui.css 体积上限，以及引擎全局滤镜预算（同屏 ≤2）里皮肤可以占几个。
- **桌面**：16:9 主舞台在 21:9 / 1920 宽屏两侧的扩展区由谁画（引擎通用 or 皮肤背景），写进 scenes 规范。
- **现有成果**：此前竖屏版的战斗/地图 CSS 基本作废；可复用的是素材、色板、字体、首页与天鹅绒立绘版式。
