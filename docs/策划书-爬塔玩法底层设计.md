# 逆影战场 · 爬塔玩法底层设计

最后更新：2026-10-19
状态：底层模型进行中；UI 留给用户绘制

## 1. 问题诊断

当前爬塔无聊的根因不是战斗，而是**塔层被做成了三选一菜单**：

- 每层只是三个按钮，没有空间、迷雾、巡逻和路线记忆。
- 玩家可以选纯宝箱/事件路线，一路不打架到安全屋。
- 安全屋免费且没有代价，恐惧和资源压力消失。
- 警戒值只涨不疼，玩家不需要为“被发现”付出代价。
- 地图没有“下一间房可能有什么”的悬念，也没有“再走一间就撤”的贪心。

结论：继续在三个按钮上加战斗，只会变成“三选一 + 强制打架”，仍然不是爬塔。

## 2. 参考游戏与可借的点

| 游戏 | 可借的核心 | 不照搬的部分 |
|---|---|---|
| Persona 5 / P5R 殿堂 | 空间潜入、迷雾、警戒、掩体、安全屋、预告信、Boss、资源压力 | 不复制剧情、角色、美术和音乐 |
| Persona 3 Tartarus | 常驻塔、逐层推进、疲劳/资源、满月 Boss、队伍编成 | 不做真实日历和学校生活 |
| Slay the Spire | 分支地图、精英风险、营地取舍、每步都知道代价 | 不做卡牌构筑 |
| Hades | 房间奖励选择、每次 run 有构筑差异、死亡后长期成长 | 不做实时动作 |
| Darkest Dungeon | 消耗战、压力/火光、侦察、撤退代价、好奇心惩罚 | 不做队伍永久死亡 |
| Etrian Odyssey | 手动地图、FOE 巡逻、捷径、采集风险 | 不做全手绘地图 UI |
| Dungeon of the Endless | 房间资源、照明、波次压力、路线守护 | 不做塔防 |
| Risk of Rain 2 | 时间压力、越贪越强也越危险 | 不做射击 |
| Monster Train / Roguebook | 路线与构筑联动、精英奖励 | 不做卡牌 |
| Inscryption | 节点地图的仪式感、路径记忆 | 不做卡牌叙事 |

共同原则：

1. **每步都有代价**：移动、开箱、绕路、休息都要消耗资源或推高危险。
2. **信息不完全**：先看到雾里的轮廓，再决定是否深入。
3. **强制遭遇**：守卫/巡逻让玩家不能一路空手到安全屋。
4. **风险收益**：多拿一件宝箱，可能多一场精英战。
5. **可撤退**：知道什么时候走，是玩法的一部分。
6. **可回看**：走错的路、留下的钥匙、打开的捷径要能被记住。

## 3. 新塔层模型

### 3.1 房间地图

- 每层 5×5 房间；入口在左下，出口在右上。
- 房间类型：入口、出口、守卫、影子、宝箱、事件、机关、钥匙、安全屋、空房。
- 初始只揭示入口及相邻房间；移动后揭示四周。
- 守卫挡在出口前；击破守卫或拿到钥匙才能打开出口。
- 每层至少一场守卫战；非战斗路线每层最多一次。
- 安全屋只出现在第 4/8 层，且必须先清理该层守卫。

### 3.2 移动与警戒

- 每次移动消耗 1 回合，警戒 +1。
- 进入影子/守卫房间，警戒 +8；被先制时开局扣 15% 当前 HP。
- 警戒到 100 进入 ALERT：下一场战斗先制，巡逻压力上升。
- 安全屋休息一次，警戒 -20，ALERT 解除；不能反复刷。

### 3.3 钥匙与锁门

- 钥匙房在支路；拿钥匙会多走几步，也可能多遇一场影子。
- 出口默认锁闭；击破守卫可以直接解锁，钥匙提供另一条路。
- 后续可加“捷径门”：打开后可以从入口快速回到该层。

### 3.4 资源与撤退

- HP/SP、弹药、道具、Persona SP、装备都跨房间保留。
- 撤退保留已拿到的战利品，但失去未完成的请求奖励。
- 安全屋不是免费回满：只恢复一部分，且消耗本层的一次休息。

## 4. 底层 API

`floor-map.js` 已提供：

- `createFloorMap({ floor, stratum, seed })`：生成 5×5 房间、入口/出口、守卫、钥匙、宝箱、事件、机关、影子、安全屋。
- `createExplorationState(map)`：初始化玩家位置、迷雾、警戒、钥匙、回合。
- `move(state, direction)`：移动、揭雾、触发遭遇/锁门/越界。
- `resolveEncounter(state, { won })`：结算守卫/影子；守卫死亡解锁出口。
- `takeKey` / `openChest` / `disarmTrap` / `triggerTrap` / `restInSafeRoom`。
- `visibleRooms(state)`：UI 只渲染已揭示房间。

UI 需要做的只是：

- 画房间格子、迷雾、玩家、守卫、宝箱、钥匙、安全屋、出口。
- 点击方向或房间调用 `move`。
- 遭遇时打开战斗；战斗结束调用 `resolveEncounter`。
- 用 `state.security`、`state.keys`、`state.guardianDefeated` 做 HUD。

## 5. 与现有系统的关系

- 战斗仍用现有 P5Battle；房间模型只负责“为什么打、在哪里打、打完得到什么”。
- Persona/装备/技能卡/网络融合/XP 不改，继续作为爬塔准备和成长。
- 天鹅绒、商店、NPC 仍在塔外据点。
- 无尽模式复用房间地图，层数与警戒递增。
- 四套主题只换皮，不改变房间规则。

## 6. 分步落地

1. 底层模型：`floor-map.js` + 单测（已完成第一版）。
2. 把 `dungeon-run` 的 12 层流程接到房间地图：一层一图，守卫/出口/安全屋/机关对齐。
3. 塔层 UI：用户绘制；先接 5×5 房间、迷雾、HUD 和移动。
4. 战斗回接：进入影子/守卫房间触发 P5Battle；胜利后 `resolveEncounter`。
5. 事件/宝箱/钥匙/安全屋 UI 接入。
6. 三塔规则、请求、NPC、无尽模式复用同一地图模型。

## 7. 验收

- 同一层至少一场守卫战；不能空手直达安全屋。
- 走不同路线会得到不同宝箱/钥匙/机关结果。
- 安全屋只恢复一次，警戒和 HP/SP 跨房间保留。
- 玩家能看懂“为什么被发现”“为什么出口锁着”“为什么这场战斗先制”。
- 任何一层都能撤退，并保留已拿到的战利品。
